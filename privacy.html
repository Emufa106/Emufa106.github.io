Personal Drive Backup

Privacy Policy

Last updated: 7 November 2026

This policy describes the Personal Drive Backup application operated by its account owner. The application is designed for the operator's own backups, not general public use.

Data accessed and purpose

The application reads metadata about its configured Google Drive backup folder and matching archive files, uploads new backup ZIP archives from a private GitHub Actions workflow, and downloads matching archives for integrity verification. Archives contain the files selected by the workflow. Verification examines archive bytes, file names, byte counts and cryptographic hashes.

The application requests the full Google Drive scope. This permission can grant access to all Drive files available to the authorizing account; it is not a folder-only permission. The implemented archival workflow uses this access to work with its designated existing folder and matching backup archives. It does not implement deletion of existing files, overwriting of existing archives or changes to sharing permissions.

Where data is processed and stored

GitHub Actions runners process the selected source files and downloaded archive for packaging and verification. Google Drive stores the backup archives. The private GitHub repository and its workflow artifacts can store verification receipts containing file identities, links, sizes, hashes, status and error summaries. OAuth credentials are stored as a GitHub Actions secret and supplied to the runner at execution time. The workflow exchanges the refresh token with Google for a short-lived access token.

The archival workflow is designed to omit OAuth client secrets, refresh tokens and access tokens from its reports and logs. Credentials must not be committed to source control or entered into this public information website.

Use and sharing

Google and GitHub process data as needed to provide authorization, storage, hosting and workflow execution. The application does not sell Google user data, use it for advertising, or intentionally publish backup contents. Backup files remain subject to the existing permissions of their Drive destination; this application does not change those permissions.

Personal Drive Backup's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Retention and deletion

There is no automatic archive-pruning operation. Backups remain in Google Drive until the account owner removes them or changes the applicable retention settings. Compact receipts committed to the private repository remain in its history until the owner removes them. Workflow artifacts are subject to their configured GitHub retention period; the dedicated archive-check workflow currently sets 30 days.

The account owner can delete backup archives in Google Drive, remove workflow artifacts and stored credentials in GitHub, and disable the archival workflow. Revoking OAuth access stops future authorized access but does not automatically delete existing backups or receipts.

Control and revocation

The authorizing user can review and revoke the application's access through Google Account third-party connections. A revoked, expired or otherwise invalid credential will prevent future unattended backups until authorization is restored.

This public information website

These static information pages contain no sign-in form, credential collection, advertising scripts or analytics scripts added by the operator. The hosting provider, GitHub Pages, may process visitor network information as described in GitHub's Privacy Statement.

Contact and policy changes

For questions or removal requests, use the support email displayed for Personal Drive Backup on Google's OAuth consent screen. The operator will update this policy when the application's data practices change.
